# LiveOps Harness

**面向直播运营的 Agent 执行工作台：让商品准备有依据，让播中操作可确认，让异常任务可恢复。**

直播运营需要同时处理选品、口播、库存、改价和优惠券。自然语言助理可以降低操作成本，但涉及商品和资金的动作还需要明确参数、人工确认与可靠执行。LiveOps Harness 将这些要求落实为业务流程：模型理解需求并提出候选动作，运行框架负责检查权限与参数、组织任务、保存状态并记录执行结果。

项目覆盖播前准备、播中运营和播后复盘，提供可直接运行的网页工作台。默认使用本地数据和离线解析器；配置模型服务后，可启用自然语言解析、运营建议和口播生成。业务执行使用模拟环境，便于复现状态变化和故障恢复。

## 业务场景与解决的问题

| 场景 | 业务难题 | 系统如何处理 |
|---|---|---|
| 播前准备 | 多款商品逐一整理资料、写手卡和核对事实，重复劳动多 | 选品、文案、核验、汇总按 DAG 协作；独立商品可并行处理，失败后恢复对应分支 |
| 连续追问 | “它”“第二款”依赖讨论中的商品和推荐顺序，容易串品 | 保存商品焦点、列表来源与版本；存在歧义时追问，方案变化后使旧引用失效 |
| 调整商品方案 | 预算变化或替换一款商品，整份材料重做成本高 | 将目标和范围整理成任务规格；局部重规划受影响的任务，保留可复用结果 |
| 改价与发券 | 用户没说清金额、张数，模型可能自行补全 | 将候选参数与用户原话核对；缺失或冲突时转为澄清，不进入业务写入 |
| 等待审批 | 主播确认之前，价格、库存或直播阶段可能已经变化 | 高风险动作持久化暂停；恢复后在提交事务中重新校验状态版本和业务限制 |
| 重复请求 | 网络重试、重复点击可能导致多次改价或发券 | 请求身份校验、幂等键与操作账本配合，重放已完成结果 |
| 平台响应丢失 | 请求超时不代表平台执行失败，重发可能重复发券 | 保存待执行操作与结果未知状态；查询回执并对账，无法确认时转人工处理 |
| 播后复盘 | 只看聊天记录难以分清建议、审批和实际执行 | 保留指令、审批、检查、业务提交与材料来源，支持按操作回查 |

## 技术栈

| 层次 | 技术 | 作用 |
|---|---|---|
| 服务接口 | Python、FastAPI、Pydantic | HTTP API、输入输出契约与参数校验 |
| 流程编排 | LangGraph、SQLite Checkpoint | 指令状态机、高风险暂停和跨进程恢复 |
| 任务协作 | 有界 DAG、后台 Worker、任务租约 | 多角色分工、同层并行、断点与失败分支恢复 |
| 数据与审计 | SQLite、事务、状态版本、幂等账本 | 保存商品事实、审批记录、操作结果和审计事件 |
| 模型接入 | HTTPX、兼容 Chat Completions 的接口 | 结构化动作解析、运营建议与手卡生成 |
| 网页工作台 | HTML、CSS、JavaScript、SSE | 指令交互、审批、材料查看与任务进度 |
| 验证与交付 | pytest、HTTP 冒烟检查、GitHub Actions | 回归测试、真实服务检查与持续集成 |

## 核心设计

### 1. 理解需求与执行操作分层

模型返回受限的 JSON 候选动作，后端根据动作契约分发。商品、金额、张数、业务限制和执行资格由代码核对；模型生成的字段本身不构成授权。

```text
加载业务状态 → 理解指令 → 原话核对与字段规范化 → 契约与风险检查
                                                        │
                          缺参或歧义 ← 澄清               │
                          高风险动作 → 保存断点 → 人工审批
                                                        ↓
                           提交时复核 → 幂等写入与审计 → 返回结果
```

例如，“给面霜发 10 元券”缺少张数，会要求补充完整指令。“给面霜发 10 元券 20 张”形成明确提案后才进入审批；执行前还会检查券后价、数量限制和状态版本。

### 2. 材料准备与业务写入分开

备播链负责整理和审核材料，改价、切品和发券通过独立指令链执行。角色按依赖交接产物，通过技能许可限制访问范围，避免文案中的建议直接触发业务操作。

```text
选品 ─┬─ 商品 A 手卡 → 事实与合规核验 ─┐
      ├─ 商品 B 手卡 → 事实与合规核验 ─┼─ 汇总材料
      └─ 商品 C 手卡 → 事实与合规核验 ─┘
                         │
                         └─ 不通过 → 问题码反馈 → 有限修订 → 再核验
```

准备链采用固定的角色与任务模板，限制商品范围、任务步数、修订轮数和模型预算。后台任务通过 SSE 汇报进度，关闭页面后仍可继续；任务状态持久化，支持恢复、取消和局部重规划。

### 3. 用结构化状态承接对话

播前、播中、播后维护各自的工作状态，记录商品焦点、推荐列表、预算、排除商品和明确偏好。模型上下文只包含相关商品、有限的近期对话和结构化状态；完整材料外置保存，按需回查。

“第二款”绑定到具体列表和来源，而不是直接取货盘第二行。历史回答用于理解追问，执行时的价格与库存仍从业务库读取。

### 4. 在提交位置保证可靠性

审批绑定具体动作和状态版本。提交事务重新检查直播状态、商品版本及引用是否有效，再将业务变更、幂等记录和审计事件一起写入，减少检查完成后状态变化造成的错误。

发券支持本地适配器和独立账本的模拟平台。模拟远端使用持久化 outbox 保存操作；响应丢失时进入 `unknown`，通过回执核对恢复。查询仍无法确认时进入 `manual_review`，避免盲目重发。

### 5. 把调用与失败成本纳入运行约束

模型请求记录调用次数、供应商报告的 token 和用量缺口。临时故障有限重试，解析失败按策略降级；调用预算、任务上限和修订上限共同限制执行范围。Trace 记录实际执行的检查，便于定位失败发生在理解、审批、工具还是提交阶段。

## 快速开始

需要 Python 3.11 或更新版本：

```bash
python3.11 -m venv .venv
.venv/bin/python -m pip install -r requirements.lock
.venv/bin/python -m pip install -e '.[dev]' --no-deps
.venv/bin/python -m uvicorn liveops.api:app --host 127.0.0.1 --port 8765
```

工作台：<http://127.0.0.1:8765>。API 文档：<http://127.0.0.1:8765/docs>。

默认创建演示直播间和 5 件护肤商品。业务数据保存在 `data/liveops.db`，流程断点保存在 `data/checkpoints.db`。路径可分别通过 `LIVEOPS_DB_PATH` 和 `LIVEOPS_CHECKPOINT_PATH` 配置。

### 体验一条完整业务流程

1. 输入“预算 100 元内，推荐三款开场商品并解释顺序”，查看选品结果。
2. 追问“介绍第二款”，观察商品引用与讨论焦点。
3. 在多智能体备播区生成商品手卡，查看任务进度、核验结果和材料来源。
4. 输入“给面霜发 10 元券”，查看缺参追问；重新输入完整商品、金额和张数后查看审批卡。
5. 提交改价或发券申请，在审批前通过故障演示修改库存，再确认审批，观察旧状态操作被拦截。
6. 重启服务，检查待审批命令和备播任务的持久化状态。
7. 输入“复盘本场操作”，回查已执行动作。

### 可选模型服务

导出环境变量即可接入兼容接口，`.env.example` 提供配置模板，不会自动加载：

```bash
export LIVEOPS_LLM_BASE_URL=https://your-compatible-endpoint/v1
export LIVEOPS_LLM_MODEL=your-model
export LIVEOPS_LLM_API_KEY=your-key
# 可选：让准备链中的手卡角色使用模型生成
export LIVEOPS_SPECIALIST_MODEL=your-model
```

默认 `LIVEOPS_INTENT_ROUTING=hybrid`：明确的受支持指令走规则快路径，其余请求交给配置的模型解析，两条路径经过相同的业务核对。高风险审批有效期可通过 `LIVEOPS_APPROVAL_TTL_SECONDS` 配置，默认 300 秒。

也可将私有配置放在项目外的 `~/.config/liveops-harness/deepseek.env`，并显式加载：

```bash
.venv/bin/python -m liveops.private_config -m uvicorn liveops.api:app --host 127.0.0.1 --port 8765
```

### 体验远端结果未知与对账

```bash
LIVEOPS_COUPON_BACKEND=simulated_remote .venv/bin/python -m uvicorn liveops.api:app --host 127.0.0.1 --port 8765
```

在工作台选择“提交成功但响应丢失”等仿真故障，提交并审批发券，再查询回执。独立模拟平台保存自己的执行记录；本地在核对回执后更新券记录与幂等账本。

## 主要接口

| 接口 | 用途 |
|---|---|
| `POST /api/commands` | 提交自然语言指令，返回结果、澄清或待审批提案 |
| `POST /api/commands/{command_id}/approval` | 确认或拒绝具体提案 |
| `POST /api/commands/{command_id}/reconcile` | 查询模拟远端回执并对账 |
| `GET /api/state/{live_id}` | 查询直播间商品和当前业务状态 |
| `GET /api/audit/{live_id}` | 回查业务操作与审计事件 |
| `POST /api/campaigns` | 创建有范围和预算约束的备播计划 |
| `POST /api/campaigns/{live_id}/{run_id}/start` | 将计划交给后台 Worker 推进 |
| `GET /api/campaigns/{live_id}/{run_id}/events` | 通过 SSE 获取进度，支持事件 ID 补发 |
| `POST /api/campaigns/{live_id}/{run_id}/advance` | 分阶段推进或恢复失败分支 |
| `POST /api/campaigns/{live_id}/{run_id}/cancel` | 请求在阶段边界停止计划 |
| `POST /api/campaigns/{live_id}/{run_id}/replan` | 按预期版本替换商品并局部重规划 |
| `GET /api/campaigns/{live_id}/{run_id}/artifacts/{artifact_id}` | 获取完整材料与核验产物 |
| `GET /api/campaigns/{live_id}/{run_id}/metrics` | 查看准备链的调用与用量统计 |
| `GET /api/memory/{live_id}` | 查看场景记忆、商品焦点与偏好 |
| `GET /api/contracts` | 查看登记的动作和技能契约 |

## 使用范围

当前提供本地直播业务沙箱，未接入淘宝生产接口。模拟远端不具备真实平台的网络与权限模型；服务尚未提供生产级身份鉴别。默认监听 `127.0.0.1`，适合业务验证、流程演示与故障复现。

准备链默认使用规则和模板，可为手卡角色配置独立模型。运行指标是本地统计，材料审核和操作记录不代表真实成交提升。
